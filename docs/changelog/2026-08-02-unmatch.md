# 2026-08-02 — Added Unmatch, distinct from Block

## What changed

**`docs/prd.md`:** new **"Unmatch"** paragraph in Match Browsing & Feedback. Distinct from Block (which is a trust & safety tool — mutual, immediate, silent, reversible only by explicit unblock): Unmatch covers the ordinary case of two people no longer wanting to talk. One-sided, immediate, mutual removal from both people's Messages and Matches, silent (neither party is told who unmatched or why), and — unlike Block — not permanent exclusion, since the two people could still resurface for each other later. Requires an explicit confirmation naming what's about to happen, since it deletes the conversation for both sides and can't be undone. Never requires feedback.

**`prototype/messages.html`:** added an "Unmatch" option to the message thread's "..." menu, above the existing Report/Block options. Added an `#unmatch-modal` confirm dialog matching the existing Block confirm dialog's styling, with the copy: "Are you sure? This will delete all of your messages with this match on both sides. This can't be undone."

**`prototype/assets/app.js`:** wired the new modal inside `initReportAndBlock()` — confirming shows a toast and redirects to `matches.html`, since the conversation no longer exists once unmatched (unlike Block, which stays on the page with an inline "Undo — unblock" option).

## Why it changed

Founder question: what currently happens if someone unlikes a match after messaging has already started? Nothing did — the only way to leave a conversation was Block, a trust & safety tool that's the wrong fit for an ordinary "not feeling it anymore" decision and implies something adversarial happened. Unmatch fills that gap. The confirmation step was a specific founder addition: unmatching deletes messages permanently for both people, so it needs a deliberate "are you sure" moment to prevent accidental, unrecoverable regret.
