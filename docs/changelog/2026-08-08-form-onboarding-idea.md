# 2026-08-08 — Logged idea: optional form-based profile filling

## What changed

**`docs/ideas.md`:** added an entry proposing that chat-based onboarding become optional, with a form-based alternative for filling out a profile directly. Not accepted — logged only, per this project's doc workflow.

## Why it changed

Founder feedback after real-browser testing of onboarding (and three real bugs found and fixed in the same session — see `PROGRESS.md`'s Phase 2 fixes): response times and interview complexity make chat-only onboarding feel slow. The founder asked for this to be documented for a future work session, not built now.

Flagged in the entry itself, not argued against here: this would be a real departure from a principle stated repeatedly and specifically in `vision.md`/`prd.md` ("no separate forms... that write to [My Profile] directly," "Conversational AI onboarding instead of long forms," among others) and from an early business-recommendations note calling this exact rule "load-bearing brand identity, not a nice-to-have." The entry distinguishes a narrower fix (make existing conversational onboarding faster/simpler) from the idea as literally stated (a real form-based alternative path), since they have very different implications and are worth deciding between explicitly before implementation.
